# A worked example on real data

A complete measurement on a real population with real human labels, start to
finish, with the answer checkable against a truth almost no measurement ever
has.

**You can re-run all of it right now.** Everything the chain needs is in this
directory. You do not need the corpus, a network connection, or anything beyond
this repository.

## What was measured

| | |
|---|---|
| **Population** | The Civil Comments **validation split**: 97,320 comments, CC0 1.0. `docs/STANDARDS.md` S-7.1 |
| **Estimand** | Comments that at least half of human annotators labelled toxic — `toxicity >= 0.5` |
| **Design** | Simple random sample, 1,000 of 97,320, drawn under a recorded seed |
| **Interval** | Clopper-Pearson at 95%, named in the plan because there is no default |
| **Labels** | The corpus's own human annotator fractions |

## The answer

**6.800%**, 95% interval **5.319% to 8.541%**, from 68 positives in 1,000
sampled units. The full report is [`run/report.md`](run/report.md).

**And here is the part a normal measurement cannot do.** This population is
fully labelled, so the true prevalence is knowable by census:
[`census_truth.json`](census_truth.json) records **7,671 of 97,320 = 7.8822%**,
computed over every unit.

> The interval covered the truth. 7.8822% falls inside [5.319%, 8.541%].

One interval covering once is not evidence that intervals cover 95% of the
time — that claim needs many draws, and it is the separate demonstration in
[`demo/`](../../demo/), which draws 10,000 samples per threshold and reports
what fraction covered. This example shows the *tool*; that one shows the
*method*. Read them for different things.

## Run it yourself

From this directory, with the package installed (`pip install -e .` at the
repository root):

```
prevalence-kit plan          plan.yaml                  --run run
prevalence-kit sample        plan.yaml frame.txt        --run run
prevalence-kit ingest-labels plan.yaml labels.csv       --run run
prevalence-kit estimate      plan.yaml                  --run run
prevalence-kit verify        --run run --plan plan.yaml
prevalence-kit emit-report   plan.yaml                  --run run
```

Or in the container, with no Python installation at all — built locally today,
published at the release:

```
docker build -t prevalence-kit .          # from the repository root
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD:/work" -w /work \
  prevalence-kit estimate plan.yaml --run run
```

On Linux and macOS the `--user` flag is required when mounting a directory, so
the container can write into it. `docs/SOP.md` §2 has the reason.

**You should get exactly the numbers above** — the same plan hash
`1e3202a0b6309371…`, the same 1,000 items beginning `cc-val-003997`, the same
6.800% and the same interval. The draw is a keyed hash of the seed and each
item id, not a random number generator, precisely so that this claim holds on
any machine and in any language.

`verify` should print **nine checks** and exit 0. It re-draws the sample from
the frame and recomputes the estimate from the sealed record rather than
re-reading the numbers in the report.

## Why there is no comment text here

`labels.csv` carries item identifiers and label values. **It carries no comment
text, deliberately.**

This tool exists to keep harmful content sealed — encrypted at rest, shown only
as a safe preview, every unseal logged. Publishing the text it seals, in a
repository a Trust & Safety audience reads, would contradict the product. So
the example does what the tool lets you do: `content` is an optional column, and
the whole chain runs without it.

**That is a choice, not a limitation.** Sealing still runs here — the chain
seals whatever content is present, which is why `verify` reports on 1,000 sealed
items — and the synthetic example next door carries real content including a
deliberately multi-chunk item, so the sealing and tamper-detection paths are
exercised where publishing costs nothing. Ruled at Q28 / D-54.

**The run directory is not committed either**, for the same family of reasons:
it holds the sealing key and the sealed store, and this repository's own
`.gitignore` has forbidden committing keys and sealed content since Phase 1.
`run/report.md` and `run/report.json` are here because they are the output an
auditor reads; everything else in a run is reproducible by the commands above.

## Rebuilding it from the corpus

The files here were generated by [`build_example.py`](build_example.py), which
needs the corpus and `pyarrow`:

```
python examples/real-data/build_example.py --corpus <dir-with-parquet-files>
```

`docs/STANDARDS.md` S-8.5 records how to fetch the corpus and S-7.1 records its
licence and row counts. `pyarrow` is **not** a dependency of this project and
never enters its tree — run that script in a throwaway environment, as the
coverage demonstration does.

The script runs the steps in the order a real measurement happens: it writes
the frame, pre-registers the plan, draws the sample, and **only then** builds
the labels file for exactly the drawn units — which is the point where, in a
real measurement, a human rater does the work.

## What this example does not show

- **Stratified sampling.** This is a simple random sample. The stratified path,
  its Neyman allocation and its design-based intervals are exercised in the test
  suite and validated against R `survey` and `svy`; the charter's honest-limits
  section carries their measured coverage, which is worse than you might expect
  at rare rates.
- **The Rogan-Gladen correction.** No sensitivity or specificity is supplied
  here, so the estimate is uncorrected — it measures what the labels say, not
  what a perfect labeller would have said.
- **A rare-event rate.** At 6.8% this is a comfortable regime. The interesting
  and uncomfortable behaviour of these methods happens two orders of magnitude
  lower, which is what the charter's limits and the coverage demonstration are
  about.
